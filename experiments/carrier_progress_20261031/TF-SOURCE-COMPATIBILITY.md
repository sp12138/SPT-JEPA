# TF2000 source compatibility review

Reviewed source delta: `bf184904a0a3b426ea39ee83862f088d72cfb56e` → `a499fc2b543214173ea3866b76df6636a859faa0`. The new6000 source must preserve a499 model/training/data/evaluator bytes. Strict state loading alone does not establish objective equivalence; the active path review below is separate from the CPU state contracts.

All four old TF configurations use L2 flow, rho=.8, forecast_fraction=.5, beta=.25, observed anchor, ordinary full QueryPool, and no auxiliary response query. Their recorded actions, renderer dimensions, seeds, window, data, sigma and forecast RNG seeds are retained.

`ASJepaLeWM` adds `renderer_anchor_mode="observed"` and `pool_partition="full"`. These select the original QueryPool constructor/initialization and return the exact original anchor tensor. The new partitioned class is not instantiated. The default additions do not draw RNG or alter tensor arithmetic. The only preparation change is the identity `render_anchor` wrapper; generation uses the same observed-anchor identity.

`RobustLeWM.loss` adds optional branches, all explicitly checked by the CPU loaded-model audit: `rate_prior="one-step"`, `posterior_noise_scale=1`, `flow_force_t_one=False`, `response_query_mode="none"`, and `response_query_encoded_fraction=0`. Consequently the original correlated-posterior draw and rho recurrence, conditional mean, one-step predictor/rate, private seeded forecast rollout and Bernoulli condition selection, `flow_loss`, normalization and coefficient are unchanged. The added `or rate_prior == "forecast"` does not change entry into the rollout because forecast_fraction=.5 already enters it. No response head is instantiated or used. Moving the unchanged metrics dictionary before the final return introduces no arithmetic or RNG change.

The train entry changes direct class dispatch to the factory (the same RobustLeWM target), adds explicit gradient-group audit and parameter-count bookkeeping, and exports the same model target through the factory. Optimizer grouping/hyperparameters, scheduler, loss call, sampler, native Trainer and checkpoint hooks are unchanged. The dataset files/modules, native benchmark evaluator, and tracked runtime AS-JEPA/ops code have no delta in this revision range. Old and new source manifests remain linked in preparation provenance.

This static active-path review found no operation that changes the enabled TF loss or RNG sequence; an extra real-batch numerical rerun was therefore not added. The existing default-branch regression contracts remain historical supporting evidence, not a fresh6000 performance result. The new CPU pre-audit separately verifies full-state finiteness, all model keys, strict native loading, serialized parameter order, exact native optimizer/scheduler roundtrips, the unmodified semantic config, RNG presence and the native sampler sequence. It does not claim uninterrupted-GPU bitwise equivalence. Any unexpected optional-branch value, state mismatch or failed audit blocks preparation.
