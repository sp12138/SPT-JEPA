# Existing Cube candidate-bank reuse: read-only feasibility

**Feasible without new simulation, but only a fixed first-plan candidate-ranking diagnostic. No model was run for this review.** The old bank is `B/runs/mechanism_cubeaudit_recovery_20261030/pool/case0000.npz` through `case0049.npz`, where `B=/efs/prescottsun/SPT-JEPA`. The inventory and per-file hashes are saved in `B/reports/cube-pool-reuse-review-20261031/inventory.json`.

There are50 cases×39 candidates×25 raw actions. Each archive contains raw float32 actions `[39,25,5]`, actual uint8 RGB `[39,6,224,224,3]` at raw steps0/5/10/15/20/25, separate dataset start/goal RGB, and26-step position/quaternion/effector/hold/success/qpos records. RGB is directly available for encoding; no simulator reconstruction is needed. Total compressed bank size is243,407,829 bytes. Endpoint physical cost is already `max(position_error/.03, cube_symmetry_angle/15)`, with hold3 success stored separately. Endpoint pose minimization is not a hold-success oracle.

The39 candidates comprise22 nonoracle candidates (one zero,14 Gaussian and seven old-model CEM proposals) and17 recorded-action neighborhood candidates (one recorded, its exact repeat, eight0.25-scale and seven1.0-scale perturbations). Old CEM proposals came from original/lower-beta/TF seed1/2 at11671 updates plus released LeWM, with seed20261030+1009×case,300 samples×30 iterations. They are not proposals from the twelve current models, and do not duplicate their deployed solver seed42. Nonoracle/recorded-neighborhood/all groups must remain separate. Cached nonoracle hold-success coverage is40%; all-candidate coverage82%, conditional on this bank.

Raw commands are deliberately unbounded. Coordinate fractions outside declared[-1,1] are2.8446% for Gaussian,1.60–3.664% across old CEM families,4.872% for recorded perturbation0.25,9.513% for perturbation1.0, and0% for recorded/duplicate/zero. Across the complete bank the minimum is−5.9158 and maximum4.7923. Current installed Cube does **not** clip incoming coordinates to its Box: it affine-scales commands and clips state-dependent workspace/gripper targets. Therefore reuse must retain the original raw commands. Projecting them before prediction while retaining the cached original physical outcomes would mismatch the intervention. The old generic wording about environment clipping must not be applied to Cube.

The pool's candidate initial rendered images are not bitwise identical to the dataset start image used for prediction: the old audit found maximum uint8 pixel MSE16.58. Repeated recorded actions restore qpos exactly, and the recorded endpoint is within3.07mm of its dataset goal. These checks establish useful conditional replay evidence, not exact native evaluator outcome reproducibility. Subsequent bare-repeat/reset audits showed native Cube numerical/environment variation; the saved trajectories represent one realization, not repeated-rollout averages. Do not silently replace the initial dataset image with an environment rendering or claim the bank eliminates the original reset issue.

A minimal future scoring protocol could retain all39 candidates, encode only the dataset start, dataset goal and39 actual endpoints, and execute each original model's five-step rollout on the same raw actions after its unchanged train-card scaling. That is2050 RGB frames,250 predictor calls and50 action-encoder calls per model; a conservative all12 ceiling is24,600 RGB,3000 predictor and600 action-encoder calls, zero DiT/renderer/simulation. No trajectory RGB beyond endpoints is needed for terminal GoalMSE ranking. No fit, labels for learning or optimization would occur. This is a proposed budget, not an executed task.

The identity/STATIC/STATE carriers share the frozen observation map within each seed; current2000 caches already have identical actual latents and normalization. Local6000 is also a frozen-carrier continuation. Reusing the same encoded bank across these four checkpoints per seed could reduce encoding to six unique maps (12,300 RGB ceiling). Before relying on this optimization, require exact encoder/projection/normalization tensor equality and relevant encode-source equivalence; this read-only review did not instantiate models or newly hash all selected weight tensors. If the maps are identical, their actual encoded-goal ranking is an invariant control: any difference between these readout arms must enter via predicted costs, not a changed actual representation. Cross-family raw latent errors remain incomparable; compare physical regret, conditional ranks and selection outcomes instead.

Recompute predicted and actual encoded costs for every new model. The existing `score-*` folders contain only the old seven models and cannot establish current-model behavior. Existing64-window factual caches are different trajectories and cannot replace bank endpoints or goals. Native must retain raw eval BatchNorm buffers rather than choosing calibrated buffers by task outcome.

Keep the three levels explicit: predicted terminal latent cost → true encoded terminal goal cost → true endpoint physical pose cost, plus cached hold-success of each selector. Include selected-candidate regret, near-minimum ordering and signed dynamics regret, not Spearman alone. Report paired cases and all seeds conditional on the fixed library; do not infer current CEM candidate coverage, off-policy generalization, action-ranking causality or50-step planning success. The intended discriminating question is whether STATE's lower factual MSE preserves the ordering of actionable alternatives under this old shared bank. A positive result would still not show it resists its own CEM's optimized errors; a negative result would locate a concrete ranking failure without making it the unique cause of planning performance.

No new model calls, fitting, physical rollouts or launches were made in this review. The twelve latent-context jobs are complete and held; this candidate-bank proposal requires root review before any execution.
