# S3 600-step 结论：结构丰富的标签不保证学到状态依赖

全部 12 个 S3 run 的训练、health、information、transition、planning 共 60 个
endpoint 均 exit 0。每个规划结果使用相同的 50 个任务内验证 cases。

| 任务 | symbol seed1/2 | completion seed1/2 | transform seed1/2 |
|---|---:|---:|---:|
| TwoRoom | 6 / 12% | 10 / 0% | 2 / 4% |
| Cube | 0 / 0% | 0 / 0% | 0 / 0% |

完整路径变换没有超过两个直接对照。TwoRoom 相对 symbol，transform seed1
新增成功 0 个、丢失 2 个；seed2 新增 1 个、丢失 5 个。不能用 completion
单个 seed 的 10% 选择赢家，也不能把三个不同目标的 CE 直接排名。

## 分类改善能由什么解释

使用原审计完全相同的 64 个 clip 和每 clip 8 个 query，在 CPU 重建标签；
未调用编码器、模型或物理标签。所有重建总计与 frozen audit 完全一致。

completion 在 TwoRoom 的准确率两 seed 都是 73.5677%，Cube 都是 72.8516%。
这恰好分别等于仅按「整段 / 前半段 / 后半段」选择各自多数类的准确率：

- TwoRoom 三段 no/yes 计数为 229/283、381/131、466/46。
  只预测「整段 yes、两半 no」即 (283+381+466)/1536 = 73.5677%。
- Cube 为 138/374、321/191、424/88；同一个规则即
  (374+321+424)/1536 = 72.8516%。

Cube transform 的两 seed 准确率均为 42.5130%，恰等于全局 AB 类比例
653/1536；仅按段选择多数类的准确率为 50.1302%。TwoRoom transform 为
31.5755/30.6641%，也未达到段多数类的 38.2813%。这些频率来自同一验证集，
是解释类别不平衡的描述性参照，不是训练好的独立验证 baseline。准确率相等
也不足以证明逐个预测完全相同，但没有证据要求用学会组合来解释它们。

半段确实包含所有五类：标签设计中的组合信息存在；失败不是代码只生成两个类。
整段则如理论预期只有 AB/BA。完整计数保存在 REPORT.md 和 results.json。

## 「比全零输入好」不等于使用具体环境状态

completion/transform 的 forecast CE/log(K) 明显低于把整个 latent 序列置零的
query-only 条件，但更换另一个真实 episode 的初态几乎不影响分类。
为排除不同 clip 的正负差异抵消，还计算了逐 clip 的绝对 CE 变化：

| 任务与臂 | 初态交换：逐 clip 平均绝对变化 seed1/2 | 全零序列：逐 clip 平均绝对变化 seed1/2 |
|---|---:|---:|
| TwoRoom completion | 4.43e-6 / 8.06e-6 | 0.122 / 0.205 |
| TwoRoom transform | 3.39e-6 / 5.20e-6 | 0.236 / 0.296 |
| Cube completion | 5.91e-5 / 1.09e-4 | 0.230 / 0.190 |
| Cube transform | 1.32e-4 / 8.81e-5 | 0.301 / 0.323 |

把真实 observed future 编码替换为另一个 episode 的 observed 编码，逐 clip
平均绝对变化也很小：TwoRoom completion/transform 4.2e-6–6.5e-6，Cube
8.3e-5–1.45e-4。这里的逐 clip 分数仍平均了该 clip 的 queries/contexts，
不能证明每一个 logit 完全不依赖状态。

与这些结果相容的具体机制是：编码具有共享非零中心 c，预测器产生近乎共享的
时间轨迹 g_t(c)。读取 [mask × g_t(c), mask, prototypes] 的 head 可把共同
轨迹当成额外偏置或时间特征。删除 c 与替换其中微小的 episode-specific
变化不是同一种干预。因此全零消融损失大，不足以证明利用了环境状态。
这是一种有数据支持的解释，尚未用专门的常量中心干预作因果识别。

动作并非在所有条件下完全无影响。Cube completion 换其他 episode 动作的
平均 CE/log(K) 增量为 .01133/.00849，逐 clip 平均绝对变化 .02037/.01583；
transform 分别为 .00317/.000933 和 .00599/.00244。它们表现出一定动作依赖，
但未超过上述类别先验准确率，更未转化成 Cube 规划成功。TwoRoom 的对应
逐 clip 平均绝对变化仅约 4e-5–1e-4。动作依赖也不等于正确预测反事实后果：
这里交换条件后仍使用原观测标签，只测依赖性，不声称有反事实真值。

## 预测状态与真实编码没有对齐

TwoRoom completion 的 clean rollout latent MSE 为 .262/.174，transform
为 .928/.803；真实初态到未来编码变化分别只有约 1e-7 和 1.5e-7–2.5e-7。
Cube 对应 MSE 为 .218/.203 与 .714/.702，真实变化约 2.3e-5–6.6e-5。
这些归一化误差很大，同时受微小分母影响；报告保留全部 raw 分子和分母。
即使相对微小真实变化的信息可能仍可解码，预测序列也明显偏离实际编码序列。

辅助 head 可以学会读取一个适合分类的预测序列，而原生 planner 仍要求预测
序列与目标观测编码在同一度量空间。训练目标的语义包含路径组合，不自动保证
这两个接口一致。当前预测器更像在生成分类特征，尚非准确追踪观测状态。

从统计目标看，proper CE 的最优值是目标的条件熵。若 query、动作和段位置
已解释大部分标签，则增加初始观测可带来的理想收益为
I(T; X0 | Q, A, segment)。复杂的 T 结构本身不保证这个条件信息增益大，
也不保证优化器能实现它。闭合的变换代数解决的是标签如何组合；让学习必须
保留与当前环境有关的信息，是另一个问题。这一轮没有证明 S3 解决了后者。

600 updates 仍处于 1249-update warmup 内，不能据此断言永久失败；但当前
规划、先验参照、状态交换和 latent 对齐均不支持把该三臂直接升级成长实验。
所有实际结果保留，不挑选有利 seed。没有新增 GPU 任务或训练修改。
