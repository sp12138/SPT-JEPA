# Local precision repair: validation scope

This changes only the shared chart used by the explicit raw interface. `RawConditionChartRenderer.bind_condition_chart` calls `enable_raw_precision()` on the single owned chart; constructor binding reconstructs the policy when raw-config checkpoints are loaded. No parameters, buffers, checkpoint keys, RNG draws, data, loss coefficients, posterior noise, calibration, optimizer or planner changes. Legacy chart/default paths retain their original FP32 implementation. Dynamic readout remains disabled and cannot be combined with this raw chart.

The raw chart's two linear maps and tanh use FP64 operands; the public state remains FP32. The contractive inverse and adjoint use the same local FP64 map/derivative, including residual norms, with the original iteration cap and tolerances. No global matmul/TF32 flag changes occur inside these modules, so unrelated predictor/renderer GEMMs retain their original policy. Process-global TF32 contexts are intentionally avoided.

The implicit inverse saves its unrounded FP64 solution. Backward differentiates that inverse followed by the public cast, matching ordinary autograd semantics. Both the rounded public state and rounded input adjoint receive a second residual certificate with the unchanged tolerance. Parameter-gradient reductions use the FP64 adjoint, return each input's original dtype, and then traverse the existing differentiable effective-weight normalization chain. First-order gradients only; higher-order requests continue to fail. Unattainable rounded precision also fails explicitly.

The implementation increases small-map/solver activation precision and compute. It stores one solution, not an iteration tape. The approved GPU verification uses only the actual captured full32768-slot operands, compares to an FP64 direct16×16 solve, verifies unchanged global high/TF32 policy during the new helper, tests failure propagation, and records one warm+one timed call and allocation peak. This is not an end-to-end model memory/throughput measurement or a training result.

Required CPU gates are the six raw/native identity/inverse-gradient contracts and four existing legacy numeric contracts. The nonlinear inverse contract explicitly enables the new raw precision; it also checks post-cast failure rather than silently certifying only an internal double solution. A separate strict reload check of the captured100-step model establishes raw policy reconstruction, unchanged557 keys and disabled dynamic branch.
