# Bounded native-command metric evaluation candidate

Forty-eight endpoints: eight held 6000 checkpoints × identity/decoder/rotated × original primary/fresh sets of 50 cases. The eight training-only matrices are fixed at calibration source70328dc. No new calibration, training, head, action projection, clipping rule, CEM setting, rollout horizon, sample budget or success definition is introduced.

`objective.py` replaces only the existing GoalMSE seam. It uses the same last predicted state and last goal frame, and preserves the native sum/mean reduction. Identity directly returns the original nativecost tensor. Every call independently verifies exact native identity algebra, scores that same candidate bank under all three metrics, and records cost arrays, rankings, chosen indices and input hashes. A mismatch or nonfinite matrix/cost blocks the run. The decoder and rotated costs use the previously frozen QR factors; nothing is named or computed as whitening. Recorder gains only an optional metric_names argument; its old default remains unchanged.

`evaluate.py` calls the existing benchmark_evaluate unchanged. Before evaluating it checks matrix artifact and calibration hashes, original weights/config/data provenance, source compatibility with8e, and the old6000 reference's exact manifest/checkpoint. After evaluating it retains new success outcomes and compares cases, policy/solver/protocol/normalization with the reference. Each of the16 identity endpoints stores its new and old50-case vectors and every differing index. A success discrepancy is preserved for review, not replaced with old numbers or silently treated as exact replay. Algebra/provenance/protocol failures are blocking.

The two case sets remain distinct. Their policy seeds and pair manifests are preserved. All metrics can score a common bank inside one run, but later CEM populations and physical trajectories can diverge across metrics; comparisons must respect this. Same-bank data supports within-bank order/rank analysis without assuming cross-run banks remain identical.

`prepare_evaluate.py` writes a new candidate root, copied unchanged manifests, a pinned old-reference record per model/case-set, and all48 jobs held. Proposed allocation uses dev2/dev13 only:16 slots, three serial jobs per slot. Chart gates are held complete; root must confirm actual GPU availability before activation. dev15 is reserved for the separate projection control. A preview has no source and cannot launch; after a new commit/freeze, prepare a distinct frozen root, still held. Only root may authorize activation. Projection-of-command controls are independent and are not mixed into this candidate.

CPU contracts cover exact identity tensor/RNG/input preservation, known-bank factor/quadratic rankings and explicit metric labels, nonfinite/mismatch blocking, raw rollout inputs/call counts, and exact native CEM identity candidates/actions. The existing recorder-default archive contract is rerun to check compatibility. No GPU or real-world evaluation is part of preparation.
