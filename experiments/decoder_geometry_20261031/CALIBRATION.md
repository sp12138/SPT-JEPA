# Eight-model global calibration candidate

The successful 9c3b9fd pilot remains immutable. This extension adds only `calibrate.py`, `prepare.py` and CPU accumulation contracts; it does not add a planner or alter the approved sampling rules in `core.py`.

Scope: held F64 identity / TF checkpoints at 6000, TwoRoom/Cube, seeds 1/2; eight calibration jobs on proposed dev2 GPUs 0–7. Each model uses the original task-specific 128-clip cohort, with identical per-clip indexed RNG for posterior noise, horizon, mixture choice, shifted logit-normal time, image noise and eight VJP probes. This preserves all pilot draws; no validation images/outcomes or physical targets enter estimation. Both tasks reuse already frozen training manifests. Parameters, buffers and raw checkpoint bytes must remain unchanged.

Save all 128×8×64 VJP vectors, per-clip rows/horizon/time/condition branch, and FP64 raw G. Compute Gnorm=64G/trace(G), a positive scalar rescaling only. Report raw/normalized eigenvalues, rank, trace and participation rank. Thin QR of the stacked VJP vectors supplies a 64×64 factor for nonnegative squared-norm costs, without inversion, eigenvalue clipping, a floor or identity mixture. One fixed Haar-QR rotation (seed 20261031) supplies QᵀGnormQ and its factor. No estimator parameter is selected using planning results.

Matrix names are explicitly `decoder_gram_raw`, `decoder_gram`, `rotated_gram`, `decoder_factor`, `rotated_factor`, `rotation`; these are not covariance whiteners. Future controller names remain exactly identity/decoder/rotated. A later adapter can reuse the native identity-return and common-bank recorder design, but must not relabel observation/increment whitening as decoder geometry. That adapter and planning evaluation are not dispatched here.

CPU contracts check accumulation, scalar-only normalization, identical eigenvalues under rotation, QR-factor/quadratic agreement, preserved rank deficiency and deterministic replay. Runtime checks compare the actual imported model/runtime against original 8e bytes, verify the newly frozen helper hashes, strictly load the original 6000 export, and compare complete state hashes before/after. All 128 finite probe vectors are required. Each job records wall/VJP time and peak device memory; all eight results require review before a separate planning decision. Finite matrices are not evidence of converged estimates or task improvement.

`prepare.py --root <new preview root>` writes an explicitly unlaunchable candidate with missing-source markers and HOLD. After root commits/freezes the new helper, `prepare.py --root <different new run root> --source-record <new source-record>` writes a frozen candidate, still HOLD and all jobs held. Root must explicitly authorize activation; the helper neither removes holds nor launches processes. Never change an existing candidate or its original cohorts in place.
